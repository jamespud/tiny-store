## 4. 关键结论（成功标准判定）

| 成功标准 | 判定 | 证据 |
|----------|------|------|
| RPS 天花板 ≥1400（基线 1100-1150） | **达标** | 天花板 ~1450：500 档 1449.1；1000-3000 档稳定 1398.7-1417.2；10000 档 1380.0（基线 841，+64%） |
| P99 峰值点 <3s | **达标（吞吐峰值点）** | 吞吐峰值区（500-3000 并发）P99 = 850.7/1472.2/2218.1/2965.1ms 全部 <3s；5000 档 4.6s、10000 档 ~30s（单机资源饱和，见 §5） |
| load-matrix 全绿 | **达标** | 超卖 4 档 + 幂等 4 档 + confirm 2 档全部通过（幂等 C=10000 由基线"120s 未完成"改善为 117.6s 完成） |

**总体：达标。** promotion commit 异步化使订单创建路径去掉一次同步跨服务调用（Feign commit + promotion 侧 DB 锁竞争），单机 RPS 天花板从 ~1150 提升至 ~1450（+26%），VUS=500 档 RPS +79%、P99 -67%（2615→851ms）、VUS=10000 档 RPS +64%。同并发档位 P95/P99 全面下降（-17% ~ -60%）。

## 5. 剩余瓶颈分析（异步链路背压）

1. **outbox 发布速率成为新瓶颈**：`OutboxEventPublisherScheduler` 每 5s 轮询、每批 100 条（`order.outbox.batch-size=100`），且每条事件发布后经 `markAsPublished` 做一次 SELECT+UPDATE。DB 被 createTrade 事务饱和时，实测发布速率仅 ~2-3 条/s（空闲时 ~20 条/s），而订单创建以 1400+ RPS 产生每单 5 条事件 → 积压瞬间形成（峰值 280 万条 PENDING）。
2. **30s 超时兜底触发取消级联**：commit 事件排队未发布 → `PendingCommitTimeoutScheduler`（30s 阈值、10s 周期）批量 auto-cancel → 每笔取消再写 3 条 outbox 事件（INVENTORY_RELEASE/ORDER_CLOSED/TRADE_CLOSED）→ 积压进一步加深，形成反馈循环（单次压测窗口记录 ~6 万条取消 WARN、峰值 ~2.5 万取消/分钟）。
3. **单线程 TaskScheduler 饿死发布器**：Spring 默认单线程调度器被长耗时 auto-cancel 任务独占时，outbox 发布任务完全得不到执行（实测发布在风暴期间完全停摆 20+ 分钟）。这是本分支引入的新风险点，也是压测中幂等测试首轮失败的根因（其事件排在 k6 遗留的 9.5 万条积压之后，30s 断言窗口内无法发布）。
4. **VUS=5000/10000 延迟与错误**：单机 16 核跑 8 个 JVM + Kafka + PG + Redis，资源串行化；10000 档 error 3.87%（基线 4.96%，改善但未消除）。

## 6. 后续优化方向

| 方向 | 做法 | 预期 |
|------|------|------|
| outbox 批量发布 | 提高 batch-size 至 1000 + `SELECT FOR UPDATE SKIP LOCKED` 分片抢占 + 批量标记 PUBLISHED（单条 UPDATE 改批处理） | 发布速率 20/s → 500+/s，消除积压与取消级联 |
| 调度隔离 | outbox 发布与超时兜底拆分独立线程池（`@Async`/自定义 TaskScheduler）；取消扫描加行锁防并发重复取消 | 消除单线程饿死 |
| 超时阈值放宽 | pending-timeout 从 30s 提至 60-120s（配合发布延迟）或按队列深度动态调整 | 消除正常负载下的误取消 |
| 压测方法 | 幂等测试客户端连接复用（C≤2000） | 消除连接错误噪声（基线已识别） |

## B. 异常与处理方法（压测过程记录）

- **首轮幂等 C=500 失败**：首轮按"k6 先行、matrix 后行"顺序执行，k6 遗留 ~9.5 万条 PENDING outbox 事件（FIFO 排队），测试事件 30s 断言窗口内无法发布 → 0 条 PRE_DEDUCTED 预留。判定为测试污染而非功能回归。
- **处理**：删除 k6 合成交易/预留并 TRUNCATE outbox（全部为压测合成数据），等取消级联停止后重跑 k6（干净数据见 §2/§A）与 load-matrix（§3）全部通过。
- **首轮 k6 数据**（含积压/级联干扰）：500 档 RPS 950.3/P99 3048.6，1000 档 1496.6/1517.1，10000 档 1061.2/30320——与干净重跑趋势一致（1000-5000 档同达 ≥1370 RPS），但 500/10000 档受级联 DB 负载拖累，不作为结论依据。
