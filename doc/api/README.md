# API 契约治理

本文档定义 API 契约的形态、版本策略、仓储结构与治理流程，确保接口变更的可控性与向后兼容性。

## 契约形态与适用场景

### REST API (OpenAPI)
- **适用**：对外用户接口、商家接口、管理接口
- **规范**：OpenAPI 3.0+
- **存储**：`doc/api/openapi/` 目录下按服务分子目录
- **生成**：支持服务端/客户端代码生成

### gRPC (Protocol Buffers)
- **适用**：内部服务间高性能通信（可选）
- **规范**：Proto3
- **存储**：`doc/api/proto/` 目录下按域分子目录
- **生成**：支持多语言客户端/服务端代码生成

### 异步 API (AsyncAPI)
- **适用**：事件发布/订阅契约描述
- **规范**：AsyncAPI 2.0+
- **存储**：`doc/api/asyncapi/` 目录下按域分子目录
- **用途**：文档生成、客户端代码生成

## API 路径与版本规范

### 路径规范
格式：`/api/v{版本}/{角色域}/{资源}`

#### 角色域分类
- `user`：用户接口（买家）
- `merchant`：商家接口（卖家）
- `admin`：管理接口（平台管理员）
- `internal`：内部接口（服务间调用、回调）

#### 示例
```
/api/v1/user/orders                    # 用户订单列表
/api/v1/user/orders/{id}               # 用户订单详情
/api/v1/merchant/orders/{id}/ship      # 商家发货
/api/v1/admin/orders                   # 管理员订单管理
/api/v1/internal/orders/payment-callback # 支付回调
```

### 版本策略
- **版本号**：语义化版本，主版本号在路径中体现
- **兼容性**：向后兼容优先，破坏性变更升级主版本
- **弃用策略**：
  - 新版本发布后，旧版本保持 6 个月支持期
  - 弃用接口添加 `Deprecated` 响应头
  - 提前 3 个月通知客户端升级

### HTTP 状态码规范
- `200`：成功
- `201`：创建成功
- `400`：请求参数错误
- `401`：未认证
- `403`：无权限
- `404`：资源不存在
- `409`：冲突（如幂等键冲突）
- `422`：业务逻辑错误
- `429`：限流
- `500`：服务器内部错误

- OpenAPI：`{角色域}-api.yaml`

- AsyncAPI：`{领域}-events.yaml`

## 变更管理流程

### 契约变更审查
1. **提交变更**：更新契约文件，提交 PR
2. **兼容性检查**：自动化工具检查破坏性变更
3. **业务评审**：产品/架构师审查业务影响
4. **技术评审**：相关团队审查技术影响
5. **批准发布**：变更合并后触发契约发布

### 破坏性变更流程
1. **影响评估**：评估现有客户端影响面
2. **迁移计划**：制定客户端迁移方案
3. **通知期**：提前通知客户端团队
4. **并行维护**：新旧版本并行维护期
5. **废弃下线**：按时间表下线旧版本

## 代码生成建议

### 服务端代码生成
- 从 OpenAPI 生成接口定义和模型类
- 从 Proto 生成 gRPC 服务定义
- 保持手工实现的业务逻辑独立性

### 客户端代码生成
- 支持多语言客户端 SDK 生成
- 包含错误处理和重试机制
- 提供类型安全的接口调用

### 文档生成
- 自动生成 API 文档站点
- 包含示例请求/响应
- 支持交互式 API 测试

## 最佳实践

### 设计原则
- **一致性**：遵循统一的命名和结构规范
- **可预测性**：相似功能使用相似的 API 设计
- **可扩展性**：考虑未来扩展需求
- **安全性**：敏感信息保护和权限控制

### 常见模式
- **分页**：使用 `page`/`size` 或 `offset`/`limit`
- **过滤**：使用查询参数进行条件过滤
- **排序**：使用 `sort` 参数指定排序字段
- **字段选择**：使用 `fields` 参数选择返回字段

### 避免反模式
- 避免在 URL 中暴露内部 ID
- 避免过度嵌套的资源结构
- 避免破坏 RESTful 原则的设计
- 避免不一致的错误响应格式
